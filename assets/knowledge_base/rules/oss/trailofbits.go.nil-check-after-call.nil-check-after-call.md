**Rule.** Potential `$FOO` nil dereference when `$BAR` is called

**Why.** Reported as CWE-253: Incorrect Check of Function Return Value. See https://blog.trailofbits.com/2019/11/07/attacking-go-vr-ttps/. Ported from opengrep rule `trailofbits.go.nil-check-after-call.nil-check-after-call` (generated/oss/vulns.yaml).

## Examples

Bad:

```go
$FOO.$BAR(...)
...
if $FOO != nil { ... }
$FOO.$BAR(...)
...
if $FOO == nil { ... }
$FUNC(..., $FOO.$BAR(...), ...)
...
if $FOO != nil { ... }
$FUNC(..., $FOO.$BAR(...), ...)
...
if $FOO == nil { ... }
```

Good:

```go
$FOO.$BAR(...)
...
$FOO = ...
...
if $FOO != nil { ... }
$FOO.$BAR(...)
...
..., $FOO, ... = ...
...
if $FOO == nil { ... }
$FOO.$BAR(...)
...
..., $FOO, ... = ...
...
if $FOO != nil { ... }
$FOO.$BAR(...)
...
$FOO = ...
...
if $FOO == nil { ... }
..., $FOO = $FOO.$BAR(...)
...
if $FOO == nil { ... }
..., $FOO = $FOO.$BAR(...)
...
if $FOO != nil { ... }
$FOO = $FOO.$BAR(...)
...
if $FOO == nil { ... }
$FOO = $FOO.$BAR(...)
...
if $FOO != nil { ... }
```
