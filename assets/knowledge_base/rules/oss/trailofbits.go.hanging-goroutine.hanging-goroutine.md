**Rule.** Potential goroutine leak due to unbuffered channel send inside loop or unbuffered channel receive in select block

**Why.** Reported as CWE-833: Deadlock. See https://blog.trailofbits.com/2021/11/08/discovering-goroutine-leaks-with-semgrep. Ported from opengrep rule `trailofbits.go.hanging-goroutine.hanging-goroutine` (generated/oss/vulns.yaml).

## Examples

Bad:

```go
for ... {
  ...
  go func(...) {
    ...
    $CHANNEL <- $VAL
    ...
  }(...)
}
...
$Y = <- $CHANNEL
...
for ... {
  ...
  go func(...) {
    ...
    $CHANNEL <- $VAL
    ...
  }(...)
}
...
return <- $CHANNEL
for ... {
  ...
  go func(...) {
    ...
    select {
      case ...
      case $CHANNEL <- $VAL: ...
      case ...
    }
    ...
  }(...)
...
}
...
return <- $CHANNEL
go func(...){
  ...
  $CHANNEL <- $X
  ...
}(...)
...
select {
case ...
case $Y = <- $CHANNEL: 
...
}
go func(...){
  ...
  $CHANNEL <- $X
  ...
}(...)
...
select {
case ...
case <- $CHANNEL: 
...
}
go func(...){
  ...
  $CHANNEL <- $X
  ...
}(...)
...
select {
case ...
case $Y <- $CHANNEL: 
...
}
```

Good:

```go
$CHANNEL := make(..., $T)
...
go func(...){
  ...
  $CHANNEL <- $X
  ...
}(...)
...
select {
case ...
case ...: 
  ...
  ... = <- $CHANNEL
  ...
}
go func(...){
  ...
  $CHANNEL <- $X
  ...
}(...)
...
select {
case ...
case ...: 
  ...
  <-$CHANNEL
  ...
}
```
