**Rule.** Variable `$X` is likely modified and later used on error. In some cases this could result in panics due to a nil dereference

**Why.** Reported as CWE-665: Improper Initialization. See https://blog.trailofbits.com/2019/11/07/attacking-go-vr-ttps/. Ported from opengrep rule `trailofbits.go.invalid-usage-of-modified-variable.invalid-usage-of-modified-variable` (generated/oss/audit.yaml).

## Examples

Bad:

```go
..., $X, ..., $ERR = ...
if $ERR != nil {
  ...
  <... $X.$Y ...>
}
```

Good:

```go
..., $X, ..., $ERR = ...
if $ERR != nil {
  ...
  $X, ... = ...
  ...
  <... $X.$Y ...>
}
..., $X, ..., $ERR = ...
if $ERR != nil {
  ...
  $X = ...
  ...
  <... $X.$Y ...>
}
..., $X, ..., $ERR = ...
if $ERR != nil {
  ...
  if $X != nil {
    <... $X.$Y ...>
  }
  ...
}
..., $X, ..., $ERR := ...
if $ERR != nil {
  ...
  if  $X != nil && <... $X.$Y ...> {
    ...
  }
  ...
}
```
